# 快餐店模拟经营 Demo 策划方案（原型验证版）

> 目标：用**一家快餐店**的最小可玩闭环，验证「点击操作 → 即时反馈 → 数值增长 → 解锁新内容」这条核心循环是否足够爽、足够让人想一直点下去。本方案**不含代码**，只定义玩法、UI、素材与验收标准。

---

## 0. 一句话定位
单店、单循环、无后端：把「点一下能爽到、数值在涨、解锁有惊喜」三件事做到位，就达到了原型目标。

---

## 1. 验证目标与假设

**目标**：以最低成本（单店 / 单循环 / 本地状态）验证核心循环的可玩性，为后续扩展成完整游戏收集判断依据。

**核心假设（待验证）**：
- **H1 即时反馈**：点击后 ≤100ms 内出现视觉+听觉反馈，能产生「爽点」。
- **H2 数值驱动**：金币 / 经验 / 等级等可见增长，是驱动重复点击的主因。
- **H3 解锁钩子**：新内容（菜品 / 设备 / 顾客）带来「下一个目标」，延长会话时长。

**成功信号**：测试用户在一次会话内自发完成 ≥20 次制作循环，且至少触发 1 次解锁弹窗。

---

## 2. 核心循环（Core Loop）

### 2.1 单循环（约 3–5 秒 / 次）
1. **点击「制作」** → 触发厨师动画 + 制作进度环（即时反馈①）
2. **进度满** → 弹出成品 +「金币 +N」飘字 + 音效（即时反馈②）
3. **数值增长** → 金币入账、经验条 +N、出餐数 +1
4. **判定阈值**：经验 / 金币 / 累计份数是否达标？
   - 是 → 触发**解锁弹窗**（新菜品 / 设备 / 顾客）→ 新内容出现在界面
   - 否 → 回到第 1 步

### 2.2 循环演进（滚雪球）
每解锁一次，操作区就多一个可点击对象：
- 先做「汉堡」→ 解锁「薯条」后两按钮并行 → 解锁「自动炸炉」后部分产出自动完成，点击升级为「加速 / 收菜」。
- 这样循环本身在变厚，专门验证「解锁 → 新内容 → 新点击」的滚雪球效应。

### 2.3 里程碑（解锁点，原型示例）
| 节点 | 解锁内容 | 触发条件 |
|---|---|---|
| 开张 | 汉堡 | 初始 |
| ① | 薯条 | 金币 ≥ 50 或 经验 ≥ 30 |
| ② | 可乐 | 累计制作 ≥ 30 份 |
| ③ | 套餐（高客单价） | 金币 ≥ 200 |
| ④ | 自动炸炉（半自动化） | 经验 ≥ 150 |

---

## 3. UI 设计

### 3.1 界面布局（单屏，竖屏优先）
- **顶部 HUD 条**：金币数（带图标）、等级 + 经验条、今日出餐数
- **中部场景区**：柜台 + 顾客队列（1–3 个排队头像）；制作时显示厨师动作 & 进度环
- **底部操作区**：制作按钮阵列（每个已解锁菜品一个），按钮含图标 + 名称 + 价格
- **浮层**：解锁弹窗、+金币飘字、连击提示

### 3.2 关键交互态
- 按钮：`idle / hover / active / disabled`（未解锁灰显 + 锁图标）
- 进度环：0→100% 填充 + 完成闪光
- 飘字：`+5` 金币上浮淡出
- 解锁：全屏微暗 + 卡片弹出 + 高亮新按钮

### 3.3 新手引导（可选，≤2 步）
首屏高亮「制作」按钮：「点这里做第一个汉堡」；首次解锁时提示「新菜品已解锁！」

## 4. 数值设计（原型表）

| 菜品 | 价格(金币) | 制作时长 | 经验 | 解锁条件 |
|---|---|---|---|---|
| 汉堡 | 5 | 1.5s | 2 | 初始 |
| 薯条 | 8 | 2.0s | 3 | 金币 ≥ 50 或 经验 ≥ 30 |
| 可乐 | 4 | 1.0s | 1 | 累计制作 ≥ 30 份 |
| 套餐 | 20 | 3.0s | 6 | 金币 ≥ 200 |
| 自动炸炉 | — | 自动 | — | 经验 ≥ 150（设备，非菜品） |

**等级曲线（原型用线性 + 小加速）**：Lv2 需 30 经验、Lv3 需 70、Lv4 需 120、Lv5 需 180……（后续按试玩数据调参）

## 5. 素材清单（供下一步实现）

**美术（2D，建议 64 / 128px 图标 + 场景）**
- 图标：金币、汉堡、薯条、可乐、套餐、锁、等级星
- 场景：柜台背景、厨师（制作 / 闲置两帧）、顾客头像 ×3、进度环
- UI：按钮底（4 态）、HUD 条、弹窗框、飘字底
- 特效：完成闪光、解锁光束、连击火花

**音频**
- sfx：点击、制作完成、金币入账、解锁、升级
- bgm：1 段轻快循环（可选）

**文案**
- 引导 2 句、解锁公告 ×5、连击提示、空状态文案

**工程**
- 单一页面 + 本地状态（无需后端）；数据存 `localStorage`（便于后续做「每日重置 / 留存」验证）

## 6. 验收标准（Acceptance Criteria）

### 功能验收（必过）
- [ ] 点击制作后 ≤100ms 内出现视觉 / 听觉反馈
- [ ] 一次完整循环可走通：制作 → 产出 → 金币 / 经验增长
- [ ] 每个解锁阈值触发时，对应内容正确出现且此前不可见
- [ ] 数值全程无负值 / 溢出；刷新页面后进度可恢复（localStorage）
- [ ] 无控制台报错，单店闭环不依赖任何后端

### 体验验收（验证假设）
- [ ] 招募 3–5 名非项目人员试玩，单次会话 ≥ 3 分钟
- [ ] 平均每人自发完成制作循环 ≥ 20 次
- [ ] 解锁触发率 100%（所有人都至少看到 1 次解锁弹窗）
- [ ] 试玩问卷「想继续点下去吗？」正向比例 ≥ 60%

### 可扩展验收（为下一步铺路）
- [ ] 新增菜品只需加一条配置即可上线（验证内容可扩展）
- [ ] 解锁逻辑与表现解耦，便于后续接入「任务 / 成就」系统

## 7. 下一步写代码的里程碑建议
- **M1 骨架**：单屏 HUD + 1 个制作按钮 + 金币计数（验证 点击→反馈→增长）
- **M2 循环**：进度环 + 飘字 + 经验条 + 等级
- **M3 解锁**：阈值判定 + 解锁弹窗 + 新按钮出现
- **M4 打磨**：音效、特效、localStorage 存档、新手引导
- **M5 验证**：找人试玩，跑验收清单
